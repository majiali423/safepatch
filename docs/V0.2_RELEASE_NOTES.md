# MVP v0.2.0 Release Notes

**Status:** Done — reliability-oriented, controlled code-repair Agent for small Python + pytest repos.

## What’s in v0.2

### Product hardening
- **Structured output format retry** with failure archival (`MODEL_OUTPUT_INVALID`, CLI exit 5). Format retries do not consume repair attempts.
- **Test integrity policy** (`PolicyValidator` / `TestIntegrityPolicy`): blocks deleting or weakening existing tests by default; optional `--allow-test-changes` is explicit high risk.
- **Product vs eval separation**: `SessionStatus` / `summary.status` vs evaluator `EvalStatus` / `metrics.eval_status`.
- Artifacts: full diff, public pytest logs, product `trace.jsonl` (redacted), and (when evaluating) `hidden.log` + `eval_trace.jsonl`.

### Evaluation (not in the Agent loop)
- Hidden tests live outside the public task repo (`<task_id>.hidden/`).
- After product `SUCCEEDED`, hidden suite runs only on an `eval_temp_copy`; never injected into product `working_copy` / Repo Map / model prompts.
- Sample tasks: `sample01_zero_div` (correct fix → eval success) and `sample02_normalize` (fixed dry-run hard-coded patch → product success + `HIDDEN_TESTS_FAILED`).

> **Important:** `sample02_normalize` uses a **fixed dry-run hard-coded patch** to prove the hidden-test infrastructure. It does **not** represent real LLM capability.

### Docker runtime (real negative E2E)
Verified with the product `DockerRunConfig` / `DockerPytestRunner` (no second security stack):
- `network_mode=none` (inspect + in-container IP connect failure)
- non-root `uid=1000`
- independent `TEST_TIMEOUT` classification
- container cleanup on success / assertion failure / timeout (named containers + `--rm` + force-remove fallback)

Product default timeout remains **120s**.

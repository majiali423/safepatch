# v0.3 Patch Applicability

**Scope:** exact patch preflight before approval. No fuzzy apply, MCP, PR, multi-agent, or large-repo features.

## Flow

```
propose_patch
→ policy validation
→ patch preflight (same matcher as PatchApplier)
   ├── mismatch → structured feedback → regenerate (not a repair attempt)
   └── applicable → approval (bound to patch_hash + working_tree_hash)
→ exact apply
→ attempts_used += 1
→ pytest
```

Inapplicable patches never enter approval and never consume `repair_attempts` (`attempts_used`).

## Counters

| Counter | Meaning |
|---|---|
| `format_retries` | Illegal JSON / schema |
| `patch_regeneration_retries` | Legal proposal that fails exact preflight |
| `repair_attempts` (`attempts_used`) | Patch applied successfully and pytest started |

Budget per regeneration window: initial patch + **2** regenerations. Exhaustion → terminal `PATCH_NOT_APPLICABLE` (not `FAILED_MAX_ATTEMPTS`).

## New terminal statuses

- `PATCH_NOT_APPLICABLE` — CLI exit **6**
- `PATCH_BASE_CHANGED` — approval binding invalidated; CLI exit **7**

## Shared matcher

`code_agent.patching.hunk_engine` is the sole exact hunk matcher used by:

- `PatchPreflight` (read-only, in-memory)
- `PatchApplier` (writes with rollback)

## Trace events

`patch_preflight_started`, `patch_preflight_failed`, `patch_regeneration_requested`, `patch_preflight_succeeded`, `patch_apply_failed_after_preflight`

## Compatibility

- v0.2 Full12 scores are historical and not rewritten.
- `FAILED_MAX_ATTEMPTS` remains only for post-apply pytest exhaustion.
